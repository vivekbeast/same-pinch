# DECISIONS.md — settled conflicts between the docs

When another doc disagrees with this file, this file wins.

| # | Topic | Decision |
|---|---|---|
| D1 | Timer warning colour | **Marigold** at ≤ 5 s (DESIGN_SYSTEM, MOTION, SCREENS). COMPONENTS' `stroke-pinch` is wrong. |
| D2 | App shell layouts | The shell picks one nav per family with `useFamily()`: BottomNav (phone), NavRail (tablet), Sidebar + ContextPanel (desktop). Never render all three and hide two with CSS. NavRail, Sidebar and ContextPanel are lazy chunks. |
| D3 | Responsive sizing rule (R2) | Applies to **layout containers and size variants** (shell, page frames, media, Button/Input sizes). Repeated sets live in `cva` variants. Small leaf components (chips, tiles, plates) declare only the breakpoints where the value changes. |
| D4 | Lighthouse CI data | `vite preview` proxies `/api` to `:3000`. CI starts the API against a migrated and seeded Postgres before Lighthouse runs, so `?demo=1` pages render real data. |
| D5 | Paid vs XP-only packs | Packs are stored on the device ahead of time with `is_paid = false`. Paid status is decided **when the pack is collected**: if the user has paid packs left today (by the day the pack was played), the earnings are credited, otherwise the pack gives XP only. Round responses show the ₹ amount as provisional. |
| D6 | Session cache vs revocation | The session cache lasts 60 s for normal reads. Logout and logout-all clear it on that instance, and money-moving routes (collect, payouts) always check the session in the database. |
| D7 | Handles | Anonymous sign-up generates a unique handle (`adjective_noun_123`) that matches `^[a-z0-9_]{3,20}$`. Users can change it with `PATCH /me`. |
| D8 | Old-browser fallback | Served as an external `public/legacy.js` (`nomodule`), not an inline script, because CSP is `script-src 'self'`. |
| D9 | Burnt words | Recomputed when packs are requested (BACKEND §6); there is no cron job. |
| D10 | Pack partner answers | Packs contain prompt metadata and assets only. Partner answers never leave the server before the player has submitted. |
| D11 | Age | Users must be **18+** (`ageConfirmed`). Content is also kept suitable for 16+ (CONTENT_I18N), which is stricter content, not a lower age. |
| D12 | shadcn | We don't run `shadcn init`. Radix primitives are installed directly, and our `components/ui/*` are hand-written in shadcn's style using our tokens (same result, no generator config). |
| D13 | Tooling versions | TypeScript 6.0.x (typescript-eslint supports < 6.1); ESLint 9 (jsx-a11y doesn't support ESLint 10 yet); `esbuild` overridden to a patched version. |
| D14 | Repo layout | `frontend/`, `backend/` and `shared/` are **independent packages**, not an npm workspace: each has its own package.json, lockfile and node_modules (`npm run setup` at the root installs all three). `shared/` is TS source and owns the single `zod` copy. Both apps import it as `@shared` (and import `z` from it, never from `zod` directly). The frontend resolves it through a Vite alias plus `server.fs.allow`; the backend through tsconfig `paths` (tsx), tsup `noExternal` and a Vitest alias. |
| D15 | Local DB | `backend/docker-compose.yml` runs `postgres:16-alpine` on host port **5433** (`npm run db:up`), so it never clashes with other local Postgres instances. |
| D16 | Schema refinements (phase 2) | The authoritative schema is `backend/src/db/schema.ts` + `backend/drizzle/*.sql`. Changes from DATA_MODEL.md: join tables `pack_rounds` / `daily_set_prompts` replace `uuid[]` columns (so foreign keys hold); new `regions` (36 rows, FK target for every state code) and `user_days` (per-local-day packs, paid packs, ₹ and XP; drives the paid cap, ₹40 cap, flame and the weekly leaderboard); `level` and gold counters are **computed** (from `xp` and from gold `answers` over 30 days) instead of stored; `packs.paid` is null until collect (D5). |
| D17 | Money guarded by the database | `0001_money_guards.sql`: triggers make `ledger` append-only (only forward status moves: `pending_review → credited`, `pending → paid / failed`; rows are deleted only by an account-deletion cascade) and `payouts` immutable apart from settling once. Partial unique indexes allow one `earn` row per pack and one `payout` row per payout. View `user_balances` is the one definition of balance / held / pending / paid. |
| D18 | Burnt-word sample size | Burning needs at least `burn.minAnswers` (20) answers in the window; otherwise 5 seeded answers per prompt would burn every top word at once. Pre-burnt words are seeded on 9 prompts so the mechanic is visible. |
| D19 | Stable content IDs | Prompt, seed-user and seed-answer IDs come from `stableId(key)` (UUID v5-style), so reseeding never orphans packs stored offline on phones. The seed is idempotent and only replaces seed/demo users. |
| D20 | Demo account | `ritika_demo`, restore code `SAME7777` (hashed with `SESSION_PEPPER`). About 10 days of history: 7-day flame ending yesterday, 1 freeze, level 4, 18 synced regions, one settled ₹50 payout. |
| D21 | Prompt assets | Image and vibe prompts reference `/prompts/<key>-{320,480,720}.webp`. `subject` in `seed/data/prompts.ts` says what each photo must show; the files are added in the frontend phase. Sound prompts are supported by the schema but not seeded (cut list item 3). |
| D22 | Gold rounds stay hidden | Gold (test) rounds are scored, paid and displayed against a partner exactly like normal rounds. Paying ₹0 on them would reveal which round was the test. The hidden verdict lives in `answers.gold_correct` (never serialised) and drives gold accuracy → pay multiplier and `users.gold_streak`. `round_result` no longer has `gold_ok` / `gold_miss`. |
| D23 | Restore codes | Only a hash is stored, so `GET /me` returns `restoreCode: null`. The code is returned once on `POST /auth/anon` and `/auth/restore`; Settings calls `POST /auth/restore-code`, which rotates and returns a new one. The shared demo account (`SAME7777`) never rotates. `POST /auth/demo` signs straight into it (DEMO_MODE only). |
| D24 | API additions | `GET /packs/:id` (resume) and `Pack.answered` (promptIds already submitted). New error codes `PACK_INCOMPLETE` (collect before all rounds are answered), `HANDLE_TAKEN`, `INSUFFICIENT_BALANCE`. An empty `words` array is a skipped round (timer ran out). Payouts under ₹50 return `MIN_PAYOUT` from the service rather than a validation error (SECURITY §8). A player can hold at most 3 open packs: `POST /packs` then returns the oldest open one. |
| D25 | Partners and abuse | Partners are picked at random from preferred authors (gold accuracy ≥ 0.75) when any exist, else from all qualifying answers. A pack is held as `pending_review` when ≥ 3 answers are < 800 ms, or one word set is used on > 60% of rounds. A late offline pack counts for the day it was played but never moves the flame backwards. |
| D26 | Tests | `npm test --prefix backend` drops and recreates `<db>_test` (migrate + seed) on every run, so dev data is never touched. Unit (rules, match engine), schema (constraints, triggers, role) and API (supertest) suites run against real Postgres. |
| D27 | Account security in three stages | **1. Play now:** anonymous account + session cookie + restore code; no sign-up form. **2. Secure it (optional):** link a Google account. Linking keeps the same user row, so all progress stays; a linked Google account is another sign-in route next to the restore code. Google ids are stored only as keyed hashes plus a masked email. Phone/SMS was considered and **removed** (no SMS budget; Google covers recovery). **3. Payouts after verification:** `payout.mode` is `simulated` (needs a linked identity), `disabled`, or `live` (also needs `users.kyc_status = verified` **and** a payout partner, which isn't built, so it stays closed). `Me.payout.needs` tells the client what's missing (`identity`, `kyc`). |
| D28 | Google via the server-side redirect flow | OAuth 2.0 authorization code + PKCE (S256), with `state` and `nonce` bound to a signed, HttpOnly, 10-minute, single-use `sp_oauth` cookie. `GET /api/v1/auth/google/start?intent=login|link&returnTo=/path` → Google → `GET /api/auth/google/callback` (the registered redirect URI; path taken from `GOOGLE_REDIRECT_URI`). The server exchanges the code with the client secret, verifies the ID token against Google's keys (audience, issuer, nonce, `email_verified`), then signs in or links, and redirects to `APP_ORIGIN + returnTo` with `?signed_in=google`, `?linked=google` or `?auth_error=google_not_linked|identity_taken|google_cancelled|google_failed|signin_required|google_unavailable`. `returnTo` must be a same-app path. Signing in with an unlinked Google account opens nothing (link first, from Settings). The secret lives only in `backend/.env` / Vercel env. The API now listens on **:3000** to match the registered redirect URI. |
| D29 | Creative direction | `docs/UI_DIRECTION.md` is the upgraded visual direction and wins over DESIGN_SYSTEM.md on visual details. Violet is "office-stamp ink" (the PINCH stamp, credited stamps, badges as round seals); coral is only the flame numeral. New vernacular pieces: **Player Plate** (`KA 04 RITIKA`), **Plate Map** (36 state-code plates as a tile cartogram instead of an SVG map), **ticket-stub** ledger rows. Onboarding uses the product's own objects (plates + stamp on a paper slip) instead of stock photos. No arrows on buttons, no middle-dot meta strings, no all-caps eyebrows. Logo: the pinch gesture side-on. |
| D30 | Layout per family | The shell renders exactly one navigation per family (BottomNav / NavRail / Sidebar + ContextPanel); tablet/desktop shell pieces and every screen are lazy chunks. Screens whose structure differs branch on `useFamily()` (Play, Results, Wallet, Settings, Daily, Welcome); screens that only re-flow use responsive grids. Initial JS 123 KB gzip, CSS 11.8 KB. |
| D31 | Prompt photos | CC0 / public-domain photos from Openverse via `frontend/scripts/fetch-prompt-photos.mjs`, square WebP at 320/480/720 (q80), pinned in `content/prompt-photos.json`, credited in `content/CREDITS.md`, reviewed by hand against the content rules (no identifiable faces, no text, right subject, unambiguous gold prompts). **No per-image byte budget** (owner decision): photos are static files served from the CDN with a one-year immutable cache and lazy-loaded; this supersedes the "≤ 18 KB at 480" lines in DESIGN_SYSTEM.md §6 and PERFORMANCE.md §2. `red-umbrella` is inactive until a proper photo exists. |
| D32 | Left for the wiring phase | IndexedDB answer queue + sealed offline reveal, PWA install/update prompts and icons, Sentry, web-vitals events, Playwright journeys and Lighthouse CI. |
| D33 | Offline play (wired) | Every round is written to the IndexedDB queue (Dexie) **before** it's sent; offline it seals ("Saved…") and play continues. Verified in a real browser on dev (queue/flush/resume) and on the production build (offline reload + offline pack with cached photo). |
